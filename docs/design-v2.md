# ClinicalFaultBench 设计说明 v2.0

> 本文说明基准的数据架构、故障分类与工程形态。**v1 曾以 MIMIC-IV 为数据底座;v2 改为以纯合成 Synthea 为主实验数据源**,原因见 §1。
>
> 差异化声明与 related work 切割见 [`novelty-claim.md`](novelty-claim.md)。
> **必须守住的合规约束**:本仓库不含任何真实患者数据,`data/` 与 `results/examples/` 均在 `.gitignore` 中。

## 1. 数据源选择

### 1.1 为什么不用 MIMIC-IV 全量

三条互相独立的理由,任何一条单独成立就足够:

1. **许可层面**:MIMIC-IV 全量受 *PhysioNet Credentialed Health Data License* 约束,第 3 条明文要求持证人不得向他人共享访问权限。**该许可与个人绑定**,由第三方代为取得的数据不能转交给他人使用——授权范围不会因为数据已经躺在磁盘上而扩大。
2. **访问层面**:physionet.org 的 MIMIC 内容页对大陆 IP 返回 "Data is not available in your region due to legal or policy restrictions",文件层 403。
3. **风险层面**:即便技术上能拿到,发表时"数据来源是否合规"会成为无法自证的负担。

第 2 条的具体法源(美国 DOJ 数据安全规则对 bulk 敏感个人数据的阈值)**本轮未逐字核实,只作判断参考**;第 1 条不依赖它。

### 1.2 MIMIC-IV demo 的残余不确定性

demo 页的许可字段是 **Open Access + ODbL v1.0**(明确允许再分发),但文件区同样对大陆 IP 返回地区限制。"许可开放"与"站点封锁"并不矛盾——前者是数据授权,后者是网站访问策略。因此 demo 在大陆环境下"拿到并使用时是否同样受限"存在解释空间。

**结论:demo 降级为可选**,默认不用:

- 求稳 → 主实验与外部校验都用 Synthea(可换不同 random seed 模拟两套人群);
- 不介意 → demo 只做 100 患者的方向性校验,论文明确标注"使用 Open Access 的 ODbL demo,非凭证数据"。

**主实验建在 Synthea 上,零合规风险,不依赖上述判断。**

## 2. 三档数据、一份代码

把"评测框架"和"数据"彻底解耦,这是 v2 的核心架构决定。

| 档 | 数据 | 许可 | 用途 |
| --- | --- | --- | --- |
| **T1 合成** | **Synthea**(纯合成患者,Apache-2.0) | 零合规问题、可无限扩、可公开、可复现 | **主实验**:全部主表、严重度曲线、消融 |
| **T2 开放小样本** | MIMIC-IV demo v2.2(100 患者 / 275 住院) | Open Access + ODbL v1.0 | **外部效度校验**:证明故障效应不是合成数据特有;默认不用,见 §1.2 |
| **T3 院内私有** | 合作医院真实 EHR | 伦理批件 + 数据不出院 | **只跑不传**:代码在数据方环境运行,只回传聚合指标 |

工程含义:

- 数据适配器接口只依赖"病程时间线"这一份 schema(`src/synthea.py` 与 `src/timeline.py` 输出同构),FaultProxy 与判分器不感知数据源。
- **可移植审计套件**是产品形态:一条命令在任意环境自检并跑完全矩阵,产出聚合 JSON;原始行永不出环境。
- 已落地的 `timeline.py`(MIMIC demo 版)保留为 T2 适配器实现。

**为什么"数据不出院"在中国场景是加分项**:《数据安全法》《个人信息保护法》与医院"数据不出院"是硬约束,任何要在国内医院落地的医疗 AI 评测工具都必须回答"数据怎么不出院"。现有英文基准要求沙箱或凭证数据,都没有这个设计。

## 3. Synthea 可用性实测(1378 患者规模)

生成参数 `-p 1200 -s 20261026`,CSV 落在 `data/synthea/csv`(已 gitignore):

| 指标 | 实测值 | 判断 |
| --- | --- | --- |
| encounter / observation 总量 | 77,080 / 975,249 | 数据量级够 |
| 住院 encounter | 1,083 次 / 462 人 | — |
| **三要素齐全住院**(化验≥10 + 医嘱≥3 + 诊断>0) | **274 次** | 足够 90 个任务实例,余量 3 倍 |
| 其中富集(化验≥30 + 医嘱≥8) | 211 次 | 可做难例分层 |
| 可用率 | 274/1083 = 25% 住院 | **任务池按"可用住院"取,不按患者取** |
| 数值型化验带单位比例 | 5,377/5,377 = **100%** | F2 单位错误可用 |
| 关键化验 | CBC + 生化 + 凝血 + 血气 + 尿常规,87 个 LOINC 码 | T1"最异常化验"原料齐 |
| 住院主诉分布 | 肺癌 167(61%)、心衰 49、肾移植等待 23、COVID 21 | **病种严重偏斜** |
| 过敏记录 | 极少,且只到环境过敏原 | **F3 不能做过敏冲突** → 改"诊断特征 vs 用药禁忌"(CKD+二甲双胍、心衰+NSAIDs) |
| 中文术语覆盖 | 检验 27.6%(fluid 归一后)、**药品 1.8%** | 映射表须按 LOINC 码重建,不能沿用 MIMIC 词表 |

**病种偏斜的对策**:肺癌占可用住院 61% 是因为 Synthea 的 `lung_cancer` 模块化疗流程天然产大量住院。按病种分层抽样(每病种上限 20),把 274 次压到 94 次、7 类病种、最大占比 21.3%。

**与 30 患者试跑的数据对比修正**:小样本(33 患者/81 住院)时"可用住院 54 次、人均 1.87"是抽样噪声;扩大到 1378 患者后真实值是 274/1083。**任务池按住院数算,不按患者数算。**

**已知短板**:Synthea 是规则引擎生成的"教科书式"病程,无真实世界噪声(不依从、漏记、补录)。对策有三:①写进 limitations;②T2 demo 做外部校验;③故障注入本身就是人为加噪,合成底座的"过于干净"反而让注入效应更可归因。

## 4. 发布目标

- 主投**中文核心期刊 / CCF 中文会议**(CCKS 有医疗方向 track),周期 3–6 月;
- 保底:中文技术报告(arXiv 可选)+ GitHub 开源 + 竞赛提交;
- **国际会议不排除**:若只用 ODbL 开放的 demo 或纯合成数据,没有合规障碍;真正的约束是"用不了全量 → 规模上不去 → 顶会样本量不够"。

## 6. 数据可用性声明

主实验数据为 Synthea 纯合成患者,可公开复现(`data/` 由生成脚本产出,不入库)。
不涉及任何需要凭证访问的受限数据。院内数据档(T3)只在数据方环境运行,只回传聚合指标——这条本身即是"数据不出院"架构的真实案例。

## 7. 诚实声明(写进 Limitations)

1. 主实验数据为规则引擎合成的 Synthea,病程"教科书化",不含真实世界的记录缺失与不依从;
2. 未使用真实院内 EHR 做外部校验,规模小于英文同类基准,这是合规约束下的自觉选择;
3. Synthea 只有 7 类病种,病种分布仍偏斜;
4. 中文术语层覆盖不完整,未覆盖项不参与异常排序。
